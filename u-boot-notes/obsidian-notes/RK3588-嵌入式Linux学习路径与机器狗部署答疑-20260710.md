# RK3588 嵌入式 Linux/U-Boot 学习路径与机器狗部署答疑

## 一、开源项目与仓库

### 官方仓库
| 仓库 | 地址 | 用途 |
|------|------|------|
| rockchip-linux/u-boot | github.com/rockchip-linux/u-boot (next-dev) | 瑞芯微官方 U-Boot，基于 2017.09 深度适配 |
| rockchip-linux/kernel | github.com/rockchip-linux/kernel (develop-5.10/6.1) | 官方内核分支 |
| rockchip-linux/rkbin | github.com/rockchip-linux/rkbin | 预编译固件（DDR init/bl31/bl32） |
| rockchip-linux/build | github.com/rockchip-linux/build | 完整 SDK 构建脚本 |

### 社区项目
- **Orange Pi 5 Plus** — 性价比高，社区活跃，适合入门
- **Radxa Rock 5B** — 文档完善
- **Armbian/build** — 主流 Linux 发行版适配框架
- **主线 U-Boot** — 已包含 rock5b-rk3588_defconfig 等配置

## 二、学习路线（4 阶段）

### 阶段一：环境搭建与编译（1-2周）
1. Ubuntu 22.04 LTS + 交叉编译工具链 gcc-aarch64-linux-gnu
2. 克隆 rockchip-linux/u-boot（next-dev）编译
3. 克隆 rockchip-linux/kernel（develop-5.10）编译
4. 烧录到 SD 卡/eMMC 实际启动验证

### 阶段二：启动流程深入（2-3周）
- RK3588 启动链：ROM Code → TPL（DDR初始化）→ SPL → ATF(bl31) → U-Boot → Kernel
- 阅读 arch/arm/mach-rockchip/ 平台代码
- 理解设备树：arch/arm/dts/rk3588*.dtsi 和板级 .dts

### 阶段三：驱动开发（3-4周）
- 基础外设：GPIO、UART、I2C、SPI、PWM
- 进阶子系统：DRM（显示）、V4L2（摄像头）、input（遥控手柄）
- 机器狗相关：SPI/CAN（关节电机）、I2C（IMU）、PWM（执行器）

### 阶段四：系统定制（2-3周）
- Buildroot/Debian 根文件系统定制
- Recovery 系统与 OTA 升级
- 安全启动（Secure Boot / FIT Image 签名）

## 三、扣驱动细节的实操步骤

### 第一步：先让板子跑起来（1-2天）
1. 买 Orange Pi 5 Plus（约400元，8GB版）
2. 刷官方 Debian/Ubuntu 镜像到 SD 卡
3. USB转TTL接调试串口，波特率 1500000
4. 完整看一遍启动日志

### 第二步：读懂启动日志（3-5天）
- 逐行读串口日志，看不懂的 grep 源码
- `mmc@fe2e0000` → DTS 找节点 → 驱动代码看 probe 函数
- `Machine model: xxx` → 找对应 .dts 文件

### 第三步：改一个简单的东西（1周）
- 改 LED 呼吸灯：查原理图找 GPIO → 改 DTS 加节点 → 重编译内核 → 烧录验证
- 学会：DTS怎么改、内核怎么编译、怎么烧录验证

### 第四步：深入一个驱动（2-3周）
- 建议从 I2C 开始（IMU 传感器就是 I2C 设备）
- 阅读顺序：DTS节点 → probe函数 → read/write → 中断处理 → sysfs/ioctl
- 用 printk 加打印调试

### 第五步：用户空间验证
- 写 C/Python 程序通过 /dev/i2c-N 读 IMU 数据
- 从内核驱动到用户空间的完整通路

### 关键习惯
| 习惯 | 做法 |
|------|------|
| 串口日志永远开着 | 每次改动对比前后日志 |
| 源码和DTS对照看 | 看到 compatible 就 grep |
| 一次只改一个东西 | 避免不知道哪个导致问题 |
| 保留能用的镜像 | 烧录前备份 |
| git 管理改动 | 方便回退 |

## 四、机器狗部署架构

```
应用层：  RL策略推理（Python/C++）
          ↓
框架层：  RKNPU 推理引擎 + ROS2/自定义通信
          ↓
驱动层：  I2C(IMU) + SPI/CAN(电机) + PWM(执行器) + V4L2(摄像头)
          ↓
内核层：  Linux 5.10/6.1 + 实时补丁（PREEMPT_RT）
          ↓
启动层：  U-Boot → 加载内核+设备树 → 挂载根文件系统
```

- U-Boot 解决"板子怎么跑起来"
- Linux 驱动解决"怎么跟硬件说话"
- 系统定制解决"怎么把训练好的策略部署上去"
- Isaac Gym 仿真训练是上半场，Linux/U-Boot 是下半场（Sim2Real 部署）

## 五、关键澄清：什么时候需要改 U-Boot？

### ❌ 不需要碰 U-Boot 的场景
- 接 IMU 传感器（内核已自带 I2C 驱动 + IMU 驱动）
- 接摄像头
- 用市售开发板 + 现成传感器模块

### ✅ 需要改 U-Boot 的场景
| 事情 | 改 U-Boot | 改设备树 | 改内核 |
|------|:-:|:-:|:-:|
| 接 IMU 传感器 | ❌ | 可能加节点 | ❌ |
| 接摄像头 | ❌ | 可能配一下 | ❌ |
| 换内存芯片 | ✅ | ❌ | ❌ |
| 自定义 PCB 板子 | ✅ | ✅ | 可能 |
| 加安全启动 | ✅ | ❌ | ❌ |
| 改启动介质 | ✅ | ❌ | ❌ |

## 六、IMU 直连实操（不碰 U-Boot）

### 步骤
1. **接线**：IMU 模块 VCC/GND/SDA/SCL → RK3588 对应 I2C 引脚
2. **扫描确认**：`i2cdetect -y 3` 看到 0x68 说明硬件通了
3. **可能改设备树**（不是 U-Boot）：
   ```dts
   &i2c3 {
       status = "okay";
       imu@68 {
           compatible = "invensense,mpu6050";
           reg = <0x68>;
           interrupt-parent = <&gpio3>;
           interrupts = <18 IRQ_TYPE_EDGE_RISING>;
       };
   };
   ```
4. **用户空间读数据**：
   ```python
   import smbus
   bus = smbus.SMBus(3)
   who = bus.read_byte_data(0x68, 0x75)
   print(f"WHO_AM_I: 0x{who:02x}")
   ```

### 改设备树 ≠ 改 U-Boot
设备树是给 Linux 内核用的，改完重新编译内核（或单独编译 dtb）即可。

## 七、机器狗学习优先级

1. **现在**：买板子 + 刷系统 + 看串口日志（周末搞定）
2. **下周**：改设备树 + 重编译内核 + 烧录验证
3. **两周后**：读 I2C 驱动（对应 IMU）
4. **一个月后**：读 SPI/CAN 驱动（对应电机通信）
5. **两个月后**：部署简单 Python 控制程序，I2C 读 IMU + SPI 控制电机

等 Isaac Gym 策略训练好了，Sim2Real 部署的底层知识也同步到位。

## 八、关键概念速查

| 概念 | 说明 |
|------|------|
| rkbin | 瑞芯微预编译固件（DDR init/bl31/bl32） |
| TPL/SPL | U-Boot 两阶段加载器 |
| ATF (bl31) | ARM Trusted Firmware，安全监控模式 |
| FIT Image | Flattened Image Tree，打包 kernel+dtb+ramdisk |
| defconfig | 板级默认配置 |
| DTS/DTB | 设备树源码/二进制 |
| PREEMPT_RT | 内核实时抢占补丁，延迟降到微秒级 |
| RKNPU | RK3588 内置 6TOPS NPU |
| RGA | 2D 图形加速器 |
